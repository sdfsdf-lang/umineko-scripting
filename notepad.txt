หน้าตา CSV ตอนนี้
--------------------------------------------------------------
- ID มีชื่อผู้พูดต่อท้าย เช่น
    ep1/umi1_op:00007@Nanjo_male
    ep1/umi1_op:00003@narration       (บรรยาย)
    ep1/umi1_op:00586@unnamed_female  (ตัวประกอบไม่มีชื่อ)
- แท็กที่มีข้อความข้างในถูกแยกเป็น "ป้ายเปิด ... ป้ายปิด" เช่น
    เดิม: {p:1:when I speak the truth, I will use red}
    ใหม่: {p:1}when I speak the truth, I will use red{/p}
  ความหมายป้าย: {p:1}=red truth  {p:2}=blue truth  {i}=ตัวเอียง
  {f:5}=ชื่อแม่มด(ฟอนต์พิเศษ)  {c:สี}=สี  {en}=<...>
  {ruby}คำอ่าน{rb}คำหลัก{/ruby}
  ข้อความระหว่างป้ายแปลได้ แต่ป้ายต้องอยู่ครบ
  csv2story จะประกอบกลับเป็นแท็กเดิมให้เอง

ชื่อผู้พูดมาจากไหน (add_context.py ดึงจากไฟล์เกม ไม่ได้เดา)
--------------------------------------------------------------
ใช้ 2 ไฟล์ต่อ 1 ตอน (เช่น umi1_1):
  A) game\main\umi1_1.txt  = สคริปต์จริงของเกม (ญี่ปุ่น + คำสั่ง)
     (ตอนพิเศษอยู่ที่ game\omake\)
  B) story\ep1\jp\umi1_1.txt = บทญี่ปุ่นล้วน บรรทัดละ 1 ประโยค
บรรทัดที่ N ใน B = บรรทัดที่ N ของบทอังกฤษ story\ep1\wh\umi1_1.txt
= แถว ep1/umi1_1:000NN ใน CSV

ขั้นตอนต่อ 1 บรรทัด:
  1. เอาประโยคญี่ปุ่นบรรทัด N จาก B ไปหาใน A
     (หาตามลำดับ ใช้ตัวที่เจอครั้งแรกที่ยังไม่ถูกใช้ — แบบเดียวกับ
      ที่ update-manager.php ใช้ใส่คำแปลกลับ)
  2. ย้อนขึ้นไปหาคำสั่ง msgwnd_xxx ตัวล่าสุดก่อนประโยคนั้น
     = กล่องชื่อที่ผู้เล่นเห็นบนจอ เช่น msgwnd_but = Battler,
       msgwnd_bea = Beatrice, msgwnd_non = ไม่มีกล่องชื่อ
  3. ดูคำสั่งเสียงพากย์ [lv 0*"NN"*"..."] ที่อยู่ติดหน้าประโยค
     NN = รหัสเสียงของนักพากย์
  4. ตัดสิน:
     - มีกล่องชื่อ (ไม่ใช่ non)  -> ชื่อตัวละคร   เช่น @Battler_male
     - ไม่มีกล่องชื่อ แต่มีเสียง -> @unnamed_male / @unnamed_female
       (เพศดูจากว่าเสียง NN นี้ปกติเป็นของตัวละครเพศไหน
        ถ้าเป็นเสียงตัวประกอบรวม 00 / 99 หรือเพศไม่ชัด -> @unnamed)
     - ไม่มีกล่องชื่อ ไม่มีเสียง -> @narration (บรรยาย)
     - หาประโยคใน A ไม่เจอ -> เดาจากเครื่องหมายคำพูดภาษาอังกฤษ
       (@dialogue / @narration) — ทั้งเกมเจอแค่ 1 บรรทัด
  5. รหัส msgwnd -> ชื่อ + เพศ มาจากตาราง CHARS ใน add_context.py
     (ชื่อ = ของในเกม, เพศ = ใส่เองตามข้อมูลตัวละคร
      ตัวที่เพศไม่ตายตัว เช่น Lion, Zepar, Furfur ไม่มี _male/_female)
     ถ้าเห็นเพศผิด ให้แก้ในตาราง CHARS แล้วรันใหม่

ผลรวมทั้งเกม: มีชื่อผู้พูด 85,923 / บรรยาย 42,358 /
              ไม่เปิดชื่อ 2,873 / เดาจากเครื่องหมายคำพูด 1

ดูเองได้: เปิด game\main\umi1_1.txt ใน Notepad/VS Code

คำสั่งที่เกี่ยวข้อง (รันจากโฟลเดอร์ repo):

ส่วนที่ 6: สำหรับ AI AGENT (Technical handoff — read this first)
==============================================================
Goal: Thai fan translation of Umineko (07th-Mod umineko-scripting),
translating the "Witch-Hunt" (wh) English text into Thai. Only the
wh language slot is overwritten in place; the game is played with
language = Witch-Hunt.

Environment
- Windows, user iamna, PowerShell (use ";" not "&&"), Python 3.13
  as `python`, git. Run every th_tools command from the repo root.
- Git pushes as GitHub account sdfsdf-lang (Git Credential Manager).
  If push fails with an old account (kiichi737) or "string binding is
  invalid": use a NON-admin shell, `cmdkey /delete:git:https://github.com`
  then `git credential-manager github login`.
- Game: D:\Uminiko (contains wh.file; Thai font already installed in
  D:\Uminiko\fonts under the original font filenames). Thai line
  wrapping in-game was tested by the user and is fine.

Repo layout that matters
- story\<ep>\wh\*.txt     English dialogue (ep1..ep8, omake), 172 files.
- story\<ep>\jp\*.txt     Japanese; line N == wh line N.
- game\main\*.txt         game script: msgwnd_xxx (name box) and
                          [lv 0*"NN"*..] voice before each jp line.
- script\wh\menu.txt, header.txt, code.txt, credits.txt  UI/system.
- th_tools\               our converters (see Thai section above).
- th_work\csv\<ep>\<name>.csv + <name>.umimeta.json   story CSVs.

Story file format
- Every text line is wrapped in backticks with a trailing space,
  e.g.  `"Hello."` . Dialogue starts/ends with a straight " (the
  game renders it as 「」). Inline tags: {n} newline, {f:5:..} font,
  {p:N:..} style (p:1 red truth, p:2 blue truth, p:41/42 gold/purple),
  {c:RRGGBB:text} colour, {i:..} italic, {ruby:reading:base},
  {y:..}{n:..}, <...>, {qt}, {w:..:}, {o:..} ...
- A backtick inside text would break the line -> replaced with '.

CSV contract (TStudio)
- Columns: ID, Source, Translation, AI_Reference. Encoding utf-8-sig.
- Story IDs: "ep1/umi1_1:00001@Speaker" (speaker suffix from
  add_context.py: a character name, narration, unnamed,
  unnamed_male/female). UI IDs: "script/menu:LINE:k".
  csv2story/qa_check ignore everything after "@".
  How the speaker is found: for story/<ep>/jp line N, find that Japanese
  line in game/main|omake/<name>.txt (first unused match, same rule as
  update-manager.php); the last msgwnd_<code> before it is the name box
  (CHARS table in add_context.py maps code -> name + gender; "non" = no
  box); a [lv 0*"NN"*..] voice right before it gives the voice. Name box
  -> name; no box + voice -> unnamed[_gender of that voice]; neither ->
  narration; not found -> dialogue/narration from English quotes.
- Source holds only translatable text in SPLIT-TAG form (tagsplit.py):
  content tags become opener/closer tokens, e.g. {p:1:x} -> {p:1}x{/p},
  {c:86EF9C:san} -> {c:86EF9C}san{/c}, <Messenger> -> {en}Messenger{/en},
  {ruby:a:b} -> {ruby}a{rb}b{/ruby}. Content-free tags ({n}, {qt},
  {w:700:}, {p:4:<Japanese>}, {Comment:..}) stay single tokens.
  Tags may span lines (opener on one row, closer on a later row).
  Back-converters rejoin token by token; round trip is byte-exact.
- Wrappers (backticks, quotes, style prefixes, outer tags) live in
  .umimeta.json. Never edit or delete .umimeta.json.
- Meta files are deliberately NOT named *_meta.json because TStudio's
  "Deploy All" looks for that name. Never press Deploy All.
- AI_Reference is TStudio's "AI draft" column, NOT notes — TStudio
  never sends it to the model, and its "use draft" button copies it
  into Translation. Keep it empty.

Converters
- story2csv.py / menu2csv.py   source -> CSV (split form). --force.
- add_context.py               speaker suffix in IDs. --strip. Skips
                               files that already have _translated.csv.
- split_tags.py                convert old CSVs to split form.
                               --check / --strip / --only.
- csv2story.py ep1 [ep2 ...] [--only umi1_op] [--check]
- csv2menu.py [menu|header] [--check]
- qa_check.py ep1 [...] [script] [--only NAME] [--hide-info]
  -> th_work\qa\<target>_qa.csv. Checks: EMPTY, TAG_MISMATCH(ERROR),
  SAME_AS_SOURCE, NO_THAI, ENGLISH_LEFT, HONORIFIC, TAG_TEXT_LEFT,
  LENGTH_RATIO, UNBALANCED, BACKTICK, QUOTE_LOST, REPEATED,
  SAME_AS_PREVIOUS, GLOSSARY (th_work\glossary.csv), TOO_LONG.
- Back-converters read <name>_translated.csv if present, else the
  Translation column of <name>.csv. They rebuild from the English in
  the meta, so re-running is safe (idempotent).
- Rules: empty translation -> keep English. Tag check
  (tagsplit.tags_ok): same tokens, same counts, valid nesting, same
  cross-line carry; pairs may move within a sentence, {en} order kept.
  Failure -> keep English, report TAG. Restore source leading/trailing
  whitespace and dialogue quotes (the AI often drops them). Smart
  quotes normalised; in menu a straight " becomes “ ” ; real line
  breaks become {n}.

Translation tool
- TStudio (inside THub) Batch AI Runner (F2) -> external file queue ->
  add folder. Worker = TRunWorker in
  THub-Launcher\tools\flagship\TRun\trun_app.py.
  Each row is sent as "ID<TAB>Source" plus the batch prompt, built-in
  format rules and up to 15 matched glossary terms. No neighbouring
  batches/summary: each batch of 100 is the only context.
  Writes <name>_translated.csv, resumes from existing output, matches
  replies by ID, retries missing/rejected rows. It rejects any change
  in tag order.
- Model gemini-3.8-flash (Gemini provider), Max Tokens 32768,
  Timeout 300 s, batch 100, Tag masking OFF. Normal API calls (NOT the
  Gemini Batch API, so no 50% discount). The user enters the API key
  in TStudio themselves — never ask for it.
- Custom prompt: TStudio "🤖 ตั้งค่าคำสั่ง AI" > "⚙️ สตูดิโอ AI Prompt"
  box 3 (Batch Translation Prompt); saved in
  THub_Workspace\Umineko\.thub\profile\prompts.json.
  th_work\tstudio_prompt_addon.txt is appended there (explains @speaker
  IDs, pronoun consistency, tag markers).
- A glossary.json next to the CSVs is auto-loaded by TRun.

Known issues / gotchas
- 22 menu rows (Chiester bios, full-width digits in {p:4:..}) fail
  TStudio's check with masking OFF (its number conversion); translate
  with masking ON or by hand.
- umi1_2:00309 has Japanese outside braces; TStudio's CJK filter
  rejects it -> manual.
- "#11" (Rule #11, ~20 rows) and "~" (yo~u, ~7 rows) are treated as
  tags by TStudio.
- {o:0:..} letter puzzle is split into many fragments.
- Menu names wrapped outside Source (e.g. {p:3:{f:5:Beatrice}) are not
  translatable via CSV.
- menu.txt line 837 (save_1_07) is missing its closing "}" in the
  original; this is preserved.
- ~4,000 {f:5}Name{/f} rows use a different font; if it lacks Thai
  glyphs, keep those names in English (keep the tokens).
- Honorifics like "san" inside colour tags may be left English by the
  AI; qa_check flags HONORIFIC / TAG_TEXT_LEFT.
- Names, on/off buttons ({p:8:}), Bern hints ({p:32:}) do not
  auto-fit — keep short. Keep {p:4:<Japanese>} untouched.
- ;cache strings in menu.txt are font preload lists: do not translate;
  optionally append Thai letters to cache_chars1/2.
- Image text (graphics\menu_en\*.png) and ep8 ending subtitles
  (video\sub\end_all00_eng.ass in the game folder) are not covered by
  the CSV tools.
- Backups from tool changes: %TEMP%\th_csv_backup_before_add_context.zip,
  %TEMP%\th_backup_before_split_tags.zip.
